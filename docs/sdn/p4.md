# P4<sub>16</sub> 学习导读与速查 {#p4-language}

P4 全称为 Programming Protocol-independent Packet Processors，用于描述数据平面怎样解析、匹配、修改和输出数据包。

完整的语言讲解、环境搭建和配套实验整理在 [P4 语言中文教程](https://github.com/zhh2001/p4-language-guide-zh)。本页提供学习路线和常用写法速查，并连接本站的控制平面、遥测与实验工具笔记。语言速查以 P4<sub>16</sub> v1.2.5 为依据。

## 1 语言、架构与目标

阅读 P4 程序时，先确定它采用的架构，以及准备运行的目标：

| 层次 | 作用 | 例子 |
| --- | --- | --- |
| 语言 | 定义类型、表达式、Parser、Control、Action 和 Table 等规则 | P4<sub>16</sub> |
| 架构 | 定义处理块接口、元数据、extern 和报文处理路径 | V1Model、PSA、TNA |
| 编译器 | 检查程序，将其转换为目标配置或其他编译产物 | p4c 及其后端 |
| 目标 | 执行编译后的数据平面程序 | BMv2、可编程交换芯片 |
| 控制接口 | 安装流水线、配置表项及访问目标支持的运行时实体 | P4Runtime、BMv2 Thrift CLI |

Parser 提取报头，Control 组织表和动作的执行，Deparser 输出报头。它们怎样连接、在哪里执行校验和，以及端口和队列怎样表示，由架构规定。控制平面通过相应接口填写表项和动作数据。

## 2 学习路线

中文教程按以下顺序组织，可以穿插阅读和实验：

| 阶段 | 教程章节 | 学习重点与练习 |
| --- | --- | --- |
| 准备环境 | 第 1~3 章 | 安装工具链，运行 Hello P4，核对入端口、出端口和返回帧 |
| 掌握语言核心 | 第 4~9 章 | 学习类型、Parser、Control、表和 Deparser，再阅读 L2 转发示例 |
| 理解架构与状态 | 第 10~13 章 | 结合 IPv4 路由、ACL 和 ECMP，理解架构接口及 extern 的作用 |
| 编译、配置与调试 | 第 14~16 章 | 查看编译产物，练习 P4Runtime 配置，再了解 PSA、TNA 等架构 |

已有环境时，可以从教程根目录运行 `sudo bash examples/check-env.sh`。自检会编译 Hello P4，并验证报文能否从入端口原样返回。各编号示例的 `run.sh` 提供进一步的配置和报文验证。

## 3 常用写法速查

### 3.1 类型与报头

| 写法 | 用途与语义 |
| --- | --- |
| `bit<W>` | W 位无符号整数，适合协议字段和位运算 |
| `int<W>` | W 位有符号整数，使用二进制补码 |
| `varbit<W>` | 当前宽度可变、最大宽度为 W 位的位串 |
| `header` | 带有效位的报头类型，字段按声明顺序对应报文中的位 |
| `struct` | 组织报头或元数据，自身没有有效位 |
| `header_union` | 一组互斥的报头，同一时刻至多一个成员有效 |
| `H[N]` | N 个同类型报头或报头联合体组成的栈，容量在编译期确定 |
| `typedef` / `type` | 前者声明别名，后者建立需要显式转换的新类型 |

固定位宽运算按操作数的类型计算。需要保留更宽的结果时，先扩宽操作数。下面的片段放在 Control 的 `apply` 块中：

```p4
bit<8> value = 8w255;
bit<16> widened = (bit<16>)value + 16w1; // 256
bit<8> wrapped = value + 8w1;            // 0
```

`in` 参数复制输入值且只读，`out` 在返回时复制输出值，`inout` 同时复制输入和输出。动作的无方向参数表示动作数据，通过表调用时由表项或默认动作提供。

### 3.2 报文处理

| 写法 | 作用 |
| --- | --- |
| `packet.extract(hdr)` | 提取定长报头，成功后推进游标并使报头有效 |
| `packet.extract(hdr, bits)` | 提取含一个 `varbit` 字段的报头，`bits` 指定该字段的位数 |
| `packet.lookahead<T>()` | 查看当前位置的定长值，保持游标不变 |
| `packet.advance(bits)` | 按比特数推进游标，跳过的数据不保存为报头 |
| `transition select(...)` | 按分支顺序选择下一个 Parser 状态 |
| `verify(condition, errorCode)` | 在 Parser 中检查条件，失败时结束解析并记录错误 |
| `hdr.isValid()` | 查询报头有效位 |
| `hdr.setValid()` / `hdr.setInvalid()` | 修改有效位，字段赋值另行完成 |
| `packet.emit(hdr)` | 在 Deparser 中输出有效报头 |

新建报头的有效位和字段值分开管理。构造新报头时，应设置有效位并填写要输出的字段。报头栈通过向 `hs.next` 成功提取来推进解析索引。

### 3.3 匹配与动作

| 写法 | 含义 |
| --- | --- |
| `exact` | 字段值相等时匹配 |
| `lpm` | 最长前缀匹配 |
| `ternary` | 通过值和掩码匹配字段 |
| `default_action` | 表未命中时执行的动作 |
| `table.apply().hit` | 本次查表是否命中普通表项 |
| `table.apply().action_run` | 本次执行的动作，包括未命中时的默认动作 |

`actions` 列表列出该表允许执行的动作，有方向的动作参数在列表中绑定，无方向的动作数据由表项提供。重叠表项的获选顺序还涉及匹配种类和优先级，优先级的数值方向由控制接口规定。

`return` 结束当前函数、动作或控制块，调用者随后继续执行。`exit` 则结束当前控制调用链。丢弃报文使用架构提供的操作，例如 V1Model 的 `mark_to_drop`。

## 4 编译与验证速查

准备好工具链和完整的 `program.p4` 后，可以从程序所在目录执行：

```shell
p4c --version
p4test --std p4-16 program.p4

mkdir -p build
p4c-bm2-ss --std p4-16 --arch v1model \
  --p4runtime-files build/program.p4info.txtpb \
  -o build/program.json program.p4
```

`p4test` 检查语言规则并执行前中端处理。后一个命令面向 V1Model 和 BMv2，进一步检查目标支持范围，生成设备配置 JSON 和描述控制接口的 P4Info。两份产物来自同一次编译，供后续流水线配置使用。

实验记录应分别写明语言规范、架构、编译器和目标版本。验证转发行为时，再结合表项、输入报文、输出端口和抓包结果进行核对。
